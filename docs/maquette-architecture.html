ScoreWeb · étape 1 sur 2 · à valider avant le code

Maquette & architecture

Une interface web Node.js qui affiche la NBA et le football, avec la mise en page et le style de la page de référence (en-tête collant, onglets en pilules, cartes « Mes équipes », listes de matchs, classement dans une colonne à droite). Les données viennent de votre proxy Docker 192.168.1.74:8100 (/nbadata et /soccer). Les scores de la maquette sont des exemples basés sur des réponses réelles du proxy du 16/11/2026.

2. Architecture logicielle Node.js 20+ · Express · HTML/CSS/JS sans framework

Un petit serveur Node.js sert de passerelle (BFF) entre le navigateur et le proxy Docker. Il interroge le proxy en tâche de fond, met les deux sports au même format et sert les logos. Le navigateur ne parle qu'au serveur Node, ce qui évite les problèmes de CORS et cache l'adresse interne du proxy.

{
  "id": "401909985", "sport": "nba",

  "status": "pre | in | post",
  "time": "01:00", "clock": "Q3 4:12",
  "home": { "name", "abbr", "score", "color",

  "away": { … },

               "topScorers": [] }  // selon le sport
}

Cycle de rafraîchissement

  1. Serveur → proxy : toutes les 15 s si un match est en cours ou commence dans 10 min, sinon toutes les 5 min. Le proxy rafraîchit déjà ESPN de son côté (10 à 20 s en direct), donc on ne surcharge rien.
  2. Si le proxy ne répond pas : on garde le dernier instantané valide et on l'indique en pied de page (« données d'il y a 3 min »).
  3. Navigateur → serveur : toutes les 30 s si hasLive, sinon 5 min, et immédiatement au retour sur l'onglet (comme la référence).
  4. Logos : téléchargés une fois depuis le CDN ESPN puis servis depuis cache/logos/ avec Cache-Control de 30 jours.

Choix techniques

Node 20+Express (seule dépendance)fetch natifnode:testJS vanilla, modules ESCSS sans préprocesseur

Pas de framework côté client : la page est un rendu de chaînes HTML à partir du JSON, comme la référence. Polices Barlow Condensed + Inter, thème sombre, accent menthe, rouge pour le direct, or pour les favoris.

Le serveur peut tourner seul (npm start) ou dans un conteneur à côté du proxy (docker compose up -d).

Constat Sur le serveur Docker, /nbadata/logo/ et /soccer/logo/ renvoient 404 : les dossiers de logos ne sont pas remplis. D'où le service de logos côté Node, qui ne dépend pas de ces dossiers.

4. Points à valider

J'ai mis une proposition par défaut pour chaque point. Il suffit de me dire ce qui change.

Nom et logo

La référence est le produit d'une autre société : je reprends sa mise en page et son style, mais pas son nom ni son logo.

Proposition : « ScoreWeb », avec un logo « S » simple.

Compétitions de foot

Le proxy en suit 23. Pastilles proposées : Ligue 1, Premier League, LaLiga, Serie A, Bundesliga, Ligue des champions, Ligue Europa, Nations League, et « Coupes » qui regroupe les coupes nationales.

Liste modifiable dans config/leagues.json.

Langue et fuseau

Interface en français, heures en 24 h, fuseau Europe/Paris.

Proposition : FR uniquement pour l'instant.

Déploiement

Un conteneur séparé sur le même hôte Docker, port 3000, avec UPSTREAM_URL=http://192.168.1.74:8100.

Alternative : npm start sur votre poste.

Hors périmètre (v1)

Pas d'application installable (PWA), pas de vidéos de résumés, pas de page détaillée par match. Tout peut s'ajouter ensuite.

Quand la maquette et l'architecture vous conviennent, répondez GO, avec vos modifications s'il y en a. Je coderai alors le serveur, l'interface, les tests et le README dans ScoreWebProxy/.
